ConOps · 运营概念（组织层）

站在组织层面，描述领导想要以什么方式运作组织，可涉及多个系统的组合；用于组织长远战略规划与年度经营计划，并指导后续获取相关方需求。本课题中对应：把混合神经系统纳入康复 / 作业体系的整体设想，可同时涉及接口设备、算法平台、执行机构等多个成员系统的配合。

OpsCon · 运行概念（系统层）

针对某一特定系统，描述系统将做什么（不是怎么做）以及为什么这么做，面向使用者；定义上下环境、外部接口与互操作系统、正常与退化运行条件、正常 / 退化 / 异常场景与操作人员需求。OCD 记录运行概念，本身不是需求文档，也不指定设计方案。本课题中对应：本混合神经系统在闭环任务中的行为方式。

两者关系：一套 ConOps 给出全局画面与假设，经差距分析派生使命需求，再落到各系统的 OpsCon；一套 ConOps 可对应多个系统的 OpsCon。

BRS业务需求规格说明（Business Requirements Specification，表 4-1 框架）

BRS

机器增强的人机混合神经系统 · 业务需求规格说明

面向组织 / 业务方
1 简介Introduction

1.1 业务目的在运动功能受限者的康复训练，以及驾驶、精细作业等需要增强操控能力的场景中，为使用者开辟一条不依赖传统肢体通道的“意图—动作”通路：把神经意图接入机器执行机构，并把动作结果以感觉形式回注，缩短意图到动作的链路，降低操作负荷。

1.2 业务范围覆盖“意图采集—解码—执行—感觉反馈”闭环在业务侧的组织与运行安排；不包含植入式器械的临床注册审批、医生诊断与治疗方案制定，也不替代现有人工康复流程。

1.3 业务概况现状：运动功能恢复主要依赖康复师主导的重复训练，操作通道单一，辅助手段多为被动支撑；未来：神经信号可被机器读取与编码回注，使用者能主动控制外部机构并获得反馈，人机协同完成任务。

1.4 定义术语与缩写见本章末尾缩写表；BRS 回答组织为什么启动、要实现什么、用什么衡量成功。

1.5 主要相关方使用者（康复患者 / 驾驶员 / 作业人员）、康复或作业管理者、医疗与合规机构、研究开发团队、器件供应商、装备集成方（整车 / 外骨骼厂商）。

3 业务管理需求Business management

3.1 业务环境政策法规：医疗器械监管、人机协同安全规范、个人健康数据保护；技术基础：非侵入式 / 半侵入式电极、信号处理、外骨骼与线控底盘的成熟度；人文伦理：知情同意、长期佩戴接受度、神经数据隐私保护；同类方案：传统康复辅具、纯视觉 / 手动操控设备。

3.2 使命、目的与目标使命：扩展人的动作与感觉通道，使人在肢体通道受限或作业负荷过高时仍能完成目标动作。目的：建立双向闭环的人机协同通路。目标（定性，指标待实验定基线）：意图可被可靠识别；执行结果可被辨识地反馈；全过程安全可控；相关方可接受并可长期使用。

3.3 业务模型使用者产生意图；接口与设备方提供采集与刺激硬件；算法团队提供解码与反馈编码；集成方把机构装入装备；管理与合规方监督流程；场景方（康复室 / 驾驶舱 / 作业工位）提供使用环境与运营流程。

3.4 信息环境业务中流转的信息：神经信号特征、使用者生理与疲劳状态、执行机构位姿与力、反馈刺激记录；以端侧处理为主，研究数据按需脱敏后同步；分级授权访问，原始生理数据不公开。

4 业务运行需求Business operation

4.1 业务过程评估适配 → 佩戴与配置 → 离线校准与训练 → 在线闭环作业 → 反馈与状态记录 → 复盘调参 → 维护与退役处置。

4.2 业务运营策略与规则分级使用：先康复训练等低风险场景，再进入高负荷作业；先离线校准、后在线使用；解码置信度不足或出现异常时，系统降级为被动辅助并保持安全；每次使用前完成适配检查。

4.3 业务运行约束人体可承受的刺激强度与佩戴时长；系统功耗、发热与重量；使用环境的电磁兼容；神经数据隐私与知情同意；课程项目周期与现有实验条件限制。

4.4 业务运行质量意图理解结果可被使用者预期；反馈可被辨识；业务过程与决策可追溯；异常事件可记录、可复盘。

4.5 业务结构使用方、工程方、管理 / 合规方、供应方四类角色，职责在下方相关方清单中逐项对应。

5 提案系统初步运行概念Preliminary ConOps

5.1 初步运行概念组织层面：把本系统作为康复 / 作业体系中的一个新能力单元，与既有训练流程、装备调度和安全规范协同；各成员系统可被替换或升级，而不改变业务流程。

5.2 初步运行场景场景一：上肢康复训练——患者在康复师监督下做重复抓握动作，系统读取意图、驱动外骨骼辅助、回注触觉提示。场景二：辅助操控——作业人员通过意图通道完成精细操作，系统在人自主运动与机器辅助之间仲裁。场景三：异常降级——信号质量下降或置信度不足时，机构退回被动支撑并提醒使用者。

6 其他初步生存周期概念Lifecycle

采办：器件与软件按模块获取；部署：佩戴安装与场景适配；支持：再校准、维护与故障处理；弃置：器件回收与数据销毁。详细概念在 StRS 第 6 章展开。

7 项目约束Project constraints

课程项目周期内完成概念与原型验证；无临床级植入设备；实验受试者与场地条件有限；指标以定性论证为主，定量基线待后续实验回填。

OpsCon运行概念（面向本系统）

本系统不替代人的决策，而是在人的意图与执行机构之间做信号转换与协调。使用者先在离线校准阶段建立个人化的信号—动作映射；在线使用时，系统持续采集神经信号、解码意图、仲裁后驱动机构，并把机构状态编码回注；当信号不可靠或出现越界，系统降级为被动支撑。运行环境包括康复室、驾驶舱或作业工位；操作者即使用者本人，康复师或管理者在旁监督；系统与外部机构、算法平台通过明确接口交换信号、数据与状态。

场景一 · 上肢康复训练

SCENARIO 01 / REHABILITATION
触发
使用者在康复师监督下做抓握 / 屈伸意图动作。
参与方
使用者、康复师、接口设备、解码平台、外骨骼。
时序
采集 → 解码 → 外骨骼辅助完成动作 → 触觉 / 位置反馈回注 → 记录试次。
异常分支
信号质量差时暂停辅助，提示重新佩戴或回到校准。

场景二 · 辅助精细作业

SCENARIO 02 / ASSISTED OPERATION
触发
作业人员需要完成持续精细操作。
参与方
使用者、解码平台、执行机构 / 线控装置。
时序
意图指令与自主运动仲裁 → 机构柔顺跟随 → 力反馈回注。
异常分支
置信度不足时退化为手动，不做强介入。

场景三 · 安全降级

SCENARIO 03 / FAIL-SAFE
触发
断链、刺激超限、机构越界或使用者急停。
参与方
安全监控子系统、执行机构、使用者。
时序
联锁触发 → 机构被动保持 / 松开 → 告警提示 → 进入维护模式待检查。
异常分支
恢复前不得自动回到在线闭环，需重新校准确认。
